# 技能管理

技能 = 提示词模板（`skill.md`）+ 内置模型配置（model / VAE / CLIP）+ 内置工作流（`workflow.json`）+ 默认基础参数。
预设只读，「复制为自定义」后可编辑。节点侧的技能选择器与 `/` 快捷菜单见 [prompts.md](prompts.md)。

## 技能文件

一个技能是一个或多个 Markdown 文件（主文件 `skill.md`），头部为 YAML frontmatter
（含 `name`、`tags`、`max_tokens`、`multi_turn`、`audit` 等字段），正文即 System Prompt 内容
（带 `workflow.json` 的生图技能出图由工作流决定，正文只作帮助文档、不参与生成）：

| 来源徽章 | 存储目录 | 说明 |
|----------|----------|------|
| SYS（内置） | `skills/presets/<id>/skill.md` | 随插件分发，只读 |
| TASK（任务） | `skills/tasks/<id>/skill.md` | 内置任务技能（反推、中英互译等），只读，不在选择器显示 |
| USR（自定义） | `skills/custom/<id>/skill.md` | 用户创建，可编辑、删除 |

生图 / 生视频技能另有 `config.json`（模型 / LoRA / 尺寸 / 张数 / 前缀等已保存设置）与
`workflow.json`（API 格式工作流模板，运行时变量以 `{{...}}` 占位）。

## 智能体页怎么用技能

智能体页输入框里的 `@` 点名技能，候选分两类：

| 类别 | 认法 | 点名它的那一发 |
|------|------|----------------|
| 生成技能 | 带 `workflow.json` 且 `gen_image` / `gen_video` | 直接当 `generate_image` 的 `skill_id`；出片时写进配方的段 `skill_id` |
| 正文型技能 | 没有 `workflow.json`，`category` 是图像 / 视频提示词增强、图像反推或自定义 | 走 `generate_prompt(skill_id=…)`：正文与 `references/` 由服务端在那一趟按需读取，产出脚本 / 分镜 / 镜头表 / 成品提示词，出片那份照它写成一份新导演配方交出去 |

`task` 类不在候选里——那一发要的是配方与在跑的任务，点名它没有产出。选中的技能跨轮保持，随请求体
`skill_id` 交后端；一次运行只读一次该技能的摘要（类别、`description`、有无模板、引用文件清单），
正文不进右栏的上下文。点名正文型技能那一轮的轮次上限放宽到 20、提问上限放宽到 6（正文里的每道确认门各发一次
`ask_user`）；其他运行照旧 12 轮、最多问一次。这一档门数由后端在 `ask_user` 上拦，不只写在工具描述里：问满这一档
与重问同一道门（只差标点空格也算）都拒回，拒回原文让它按默认规格把剩下的决定定下来并交付。
答过的门（问→答）与报过流程清单的技能随焦点链落盘（`gate_answers` / `intro_skills`，`focus` 帧带出）：
它们在整条会话里都算数——同一道门不在整条会话里问第二遍，流程清单不在整条会话里重报第二遍。
外部导入的 Agent Skills 目录（`SKILL.md` + `references/`）就是第二类：`references/` 整目录随技能落盘，
由服务端在 `generate_prompt` 那一趟按需读取。

正文型技能里的长流程（视频提示词那类：多道确认门、分次产出）在那一轮多三条要求，由后端在点名那一发注入系统
提示词（`studio/agent.py` 的 `_skill_block`，非点名那条路写在 `studio/prompts/agent/system_prompt.md` 同一规则）：
**第一句话先把这套流程要走的几步列给用户**——一步一句，写明哪一步要问他、哪一步出什么产物，列完才调第一个工具；
长流程跑到中途才报步骤，用户就是陪跑到最后一刻才发现还剩一道门没问。这一条在调用点上有闸：本轮还没跟用户讲过一句话
就去调 `generate_prompt`，那一发被后端拒回一次（只拦一次，不烧轮次），把编号清单发出来再调它；清单在整条会话里
只报一次，焦点链里已经报过的技能那一发直接跑。**要用户定的方向只能走 `ask_user`**——`ask_user` 的选项在右栏是
点得到的按钮，写进正文的 `A. B. C.` 编号选项点不动，用户那一发只能自己打字；把带编号选项的问句当最终回答交回来，
那一发被后端催着改用 `ask_user`（一发最多催两次，第二次只准发这一个工具调用，认死的模型照旧交正文）。
它产出的那份文本就是本轮交付物的内容：
出片用的那份（脚本 / 分镜 / 镜头表 / 每段成片提示词）按配方法则写成**一份新导演配方**交出去（`director_plan` 分段
→ `director_save` 落配方，段提示词照抄产出、`story` 带上主题与角色参考），新配方名报给用户，跑整片与单段都从这份
配方跑，不拿它逐段裸调 `segment_run` / `director_run`；出图用的那份（图像提示词）按技能规则出图。收场那一发的
`result` 写明配方名与段数；`media` 里本轮 `director_save` 保存下来的配方名算产物（它的回执只有
`{success, name}`，没有媒体条目）。步骤清单落在时间线已有的计划行上（带工具调用的那一发内容渲染成计划卡），配方落盘照旧
刷导演页配方弹窗并出 `✅ 配方已保存` 提示——右栏与前端不为此加第二套界面。

## 技能管理窗口

技能管理有两个入口：顶栏 🅝 菜单「🗂 技能管理」打开统一窗口（左侧按分类分组的可折叠列表 + 右侧详情，
含搜索 / 新建 / 上传 / 从画布导出；分类为手风琴，默认展开「生图」，搜索时全部分类临时展开），
或节点底部技能选择器下拉内的内嵌入口。

### 创建与维护

- **新建技能** - 点击下拉底部 "+ New Skill"，在详情窗口标题栏直接输入技能名称、填写系统提示词内容后保存。
- **上传导入** - 点击下拉底部 "⬆ ZIP" 或 "⬆ Folder"，将 `.zip` 包或整个文件夹（含多个 `.md`）导入为新技能。
- **复制为副本** - 内置模板与任务技能不可删除，可一键标题栏「复制为自定义」复制为自定义副本并立即切换到该副本详情。
- **删除** - 仅用户自定义（USR）技能可删除（删除前确认），内置（SYS / TASK）受保护。

### 浏览与检索

- **搜索过滤** - 在下拉输入框中实时过滤技能（按名称 / 标签，中文技能支持拼音全拼与首字母缩写匹配）。
- **查看 / 编辑** - 悬停技能行时右侧显示浮动预览卡，点击卡片打开单技能详情窗口，默认以 Markdown 渲染预览正文；
  点「✎ 编辑」切换到原始文本编辑、「👁 预览」切回预览（新建技能直接进入编辑模式）。

### 详情窗口

- **详情窗口布局** - 主区分两栏：左「生图 / 生视频设置」、右「系统提示词内容」（面板够宽时并排等高，
  窄面板自动堆叠）；带 `workflow.json` 的技能出图由工作流决定、正文不参与生成，正文区整体移出主区、
  收进标题栏「?」徽标弹出的居中文档浮窗，浮窗内照常预览 / 编辑 / 增删附属文件（内置技能只读、无编辑入口）；
  底部「💾 保存 / 删除（垃圾桶图标）」操作条吸顶；工作流区默认折叠，点头部展开挂内嵌编辑画布。
- **技能名称** - 名称不单独占一行，直接显示在详情窗口标题栏（同导演编辑器的配方名）：点名称进入行内编辑，
  Enter / 失焦提交，Esc 还原为已保存名；改名算未保存修改，随「💾 保存」落盘，内置（SYS / TASK）技能不可改名。
- **多文件** - 一个技能可含多个 `.md` 文件，正文按文件名升序拼接；详情窗口提供下拉切换查看 / 编辑各个 `.md`
  （主文件 `skill.md` 只编辑其正文、保留 frontmatter 元数据），可新增或删除附属文件。
- **多轮开关** - 详情窗口正文区上方的 `Multi-turn (multi_turn)` 勾选框读写 frontmatter 的 `multi_turn` 字段
  （取消勾选即移除该字段）；勾选后节点底部显示多轮提示，「复制为自定义」会连同该设置一并复制。

### 窗口行为

- **左栏宽度** - 拖动左右面板之间的分隔条调整左侧列表宽度，松手记忆宽度、下次开窗沿用；双击恢复默认。
- **自动同步** - 保存、上传、复制、删除后广播更新事件，所有节点上的技能选择器立即刷新。
- **独立窗口控制** - 统一窗口无遮罩（背景画布可继续操作）：标题栏拖动移动、双击标题栏放大/还原、
  标题栏「⛶」放大铺满（留 8px 边距）/还原、右下角把手拖拽改尺寸；关闭只走「✕」（Esc 不关整窗）。

## 工作流区：内嵌编辑

打开带 `workflow.json` 的技能，工作流区默认折叠；点头部展开才把该模板挂进内嵌画布编辑：API 格式按节点类型注册表
转成 LiteGraph 图，连线按槽位名还原、widget 值按名对齐，并按技能 `config.json` 覆盖模型 / 尺寸 / 张数 /
步数 / 前缀等已保存值、注入超出模板槽位的 LoRA（提示词、种子、参考图等运行时变量原样保留）。

工具条提供「适配视图」「重新载入」与「💾 保存工作流」：写回该技能的 `workflow.json` 并同步 `config.json`
（设置区随后按新配置重载）。预设技能不改 `workflow.json`：模型 / 尺寸等值写入预设本地覆盖
（`configs/skill_overrides/`），工作流结构有变更时自动复制为自定义技能写入副本，详情随后切到副本。
画布后备缓冲按系统显示缩放（DPR）铺满盒子，widget 输入弹窗贴着鼠标落点。
模板节点 id 允许是画布导出产生的 `"193_82"` 这类非数字串，转换时统一映射成连续整数（LiteGraph 只认数字 id）。
节点位置与「⤒ 导入到画布」共用同一套布局（拓扑分层左到右、参考加载器统一钉在最左列自上而下、列内按上游
重心堆叠、同列宽度拉齐），布局在 API prompt → LiteGraph 转换时按 workflow 键算好，非数字 id 同样排开不叠块。

点头部折叠即卸载画布，再展开重挂画布。无 LiteGraph 的视图（Studio 内嵌）或技能含未注册
节点类型时挂不上画布，工作流区回落只读流程图（红框 = 节点未安装 / 模型缺失，蓝框 = 含 `{{模板变量}}`）。
只读流程图按当前设置预渲染，被设置填走值的字段在参数行写成 `字段: {{TOKEN}} = 值`（变量名写在值前，列宽截断截掉的是值不是变量），
摘要给出「🟦 N 个变量由技能设置填入」和逐个 `{{TOKEN}}` 芯片：悬停写明填在哪个节点哪个字段、值多少、控件能填什么（combo 列可选项、数值列上下限），点 📋 复制变量名；
芯片的来源行以技能里真正存在的两项设置为标题——出图尺寸 = 「基础分辨率 × 默认比例」，`{{MEGAPIXELS}}` 写的是这两项得到的宽高 ÷ 1024² 算出来的数（技能与画布都没有 megapixels 这一项设置），
`{{ASPECT_RATIO}}` 指到「默认比例」；尺寸类变量额外写明生成时按本次宽高重算，图上的数只是技能默认尺寸下的预览。

内嵌画布带 `tabindex=1` 并在挂载时聚焦。ComfyUI 给 litegraph 打的补丁把画布快捷键执行在 `app.canvas`（主画布）
上，所以内嵌画布在 litegraph 绑定事件前抢一个 capture 监听，把 Delete 删除 / Ctrl+A 全选 / Ctrl+M 静音 /
Ctrl+B 跳过 / Alt+C 折叠 / Ctrl+Shift+V 粘贴 / `.` 适配视图 改作用在内嵌子图上；空格平移与 Esc 收节点面板走
litegraph 原生。弹窗打开时拦住会打到主画布的
全局快捷键（Ctrl+Enter 排队 / Ctrl+S 保存 / Ctrl+O 打开 / Ctrl+G 成组 / Ctrl+, 设置 / Ctrl+` 日志 /
Ctrl+` 日志 / Esc 退出子图 / r 刷新节点 / w n m a 侧栏 / Alt+M）；输入框里的键与内嵌画布上的 Esc 照常放行。
内嵌子图没有撤销栈，Ctrl+Z 撤销的是主画布，结构改动用「重新载入」还原。

## 技能 ⇄ 画布

工作流区带「⤒ 导入到画布」与「💾 回写入技能」：前者把技能 `workflow.json` 按当前设置预渲染后灌入画布、
按流程图同一套布局重排节点（参考加载器 LoadImage/LoadVideo/LoadAudio 统一排到最左列自上而下，不挤进
模型加载列；先套列宽再按新尺寸排第二轮位置，加宽后重算高度的预览节点不会叠到别的节点上）；
`{{REF_IMAGE_N}}` / `{{CONTROL_IMAGE}}` 按 `config.json` 的槽位（`control_ref`）换成 LoadImage 列表里的实际图片，
画布上不残留占位符；导入成功的 toast 逐条列出被灌成数值的模板变量（灌进哪个节点哪个字段、由哪项设置算出——尺寸写「基础分辨率 × 默认比例」、megapixels 写成算出来的数、生成时按本次宽高重算），
因为画布上不再有 `{{变量}}`，画布里那个数字是技能设置算出来的值，不是技能里存的值；后者把整画布落盘该技能 `workflow.json`（预设技能不改预设本体：模型值写本地覆盖，
结构变更自动复制为自定义技能写入副本，待回写状态随之搬到副本）。
参考视频/音频槽位（`{{REF_VIDEO_N}}` / `{{REF_AUDIO_N}}`）在导出与预设里带 `mode: 4`（bypass 跳过，洋红底，比 mute 更醒目），
导入画布即默认跳过（占位文件通常不在 input 目录里，灌进 combo 会整节点红框）；回写与「📋 从画布」导出取 prompt 前临时启用、
取完还原，槽位不丢。

「📋 从画布」创建技能时先给一份变量替换清单：模型 / 文本编码器 / VAE / Seed / 张数 / 输出前缀 / 参考图 /
提示词编码由固定规则替换，画布里额外的两条候选逐条列出并默认勾上——写死的提示词原文节点
（`PrimitiveString` / `PrimitiveStringMultiline` / `StringLiteral`，沿连线穿过预览 / 开关这类透传节点找到）
和分辨率选择器 `ResolutionSelector` 的 `megapixels` / `aspect_ratio`（它的宽高喂 latent 时才算尺寸来源）。
每行显示 `节点 #id · 字段 → {{TOKEN}} = 当前值`，取消勾选的保持画布里的写死值；勾中的写进 `workflow.json`
（`{{PROMPT}}` / `{{MEGAPIXELS}}` / `{{ASPECT_RATIO}}`），技能里真正要写的两项是 `config.json` 的 `default_ratio` / `base_resolution`
（导出时同时写入）：megapixels 不是技能的一项设置，是这两项得到的宽高 ÷ 1024² 算出来的派生数。生成时出图尺寸按本次请求宽高走，
`{{MEGAPIXELS}}` 取该宽高反算的百万像素（夹在节点 0.1–16），`{{ASPECT_RATIO}}` 取 `ResolutionSelector` combo 认得的那一项（combo 里没有这一档直接报错，不提交裸比例）。
勾中的尺寸项不冻结画布上的当前值，这条规则连勾选一起写在导出对话框里，不翻文档也知道保存的不是当前宽高。
回写按已存模板同一节点同一字段的占位符复原这份勾选，勾选结果本身不写进 `config.json`。

导入成功后自动收起技能窗口（技能管理整窗关闭、独立详情弹窗收起，不再遮挡画布），画布侧只留顶栏 🅝
按钮上的绿点提示「有技能待回写」；落盘入口是 🅝 菜单里的「💾 回写入技能」（打开菜单时该条目右侧带绿点引导）。

## Studio 交接主画布

Studio 内嵌没有画布，技能详情工作流区挂「⤒ 主画布编辑」：打开主界面 `/?neo_wf_edit=<技能 id>`，主界面消费
该参数（先清掉 URL 参数，刷新不重复导入）按技能 `config.json` 与自动建议模型预渲染灌入画布，节点 widget
按技能已保存配置初始化（覆盖 `workflow.json` 里写死的 steps / seed / 尺寸等旧值，非技能控制的值原样保留）。
桌面端里这条交接在桌面端窗口内跳转（`OPEN_EXTERNAL_LINKS_IN_BROWSER = False`），主界面顶栏「🎬 新影工坊」同窗口
回到 Studio。

顶菜单「💾 回写入技能」把整画布落盘该技能 `workflow.json`，并把画布上的模型 / LoRA / 尺寸 / 张数（`batch_size` → `count`）/ 前缀同步进 `config.json`，
设置区的底图分辨率 / 提示词增强等键保留（预设只读）；导入时程序注入的主链 LoRA 节点按数量剥离（不计入模板
结构，LoRA 值只落 `config.json`）。

待回写状态绑定灌入技能时那张画布：切到其他画布 tab 时绿点收起、切回来恢复，同画布后导入的技能顶掉前一个。

## 回写确认与变更记录

### 回写确认

- **确认预览** - 回写与内嵌保存落盘前先弹确认预览：列出相对该技能的变更清单（`config.json` 键值、LoRA、
  节点数量、连线数、`requires_ref`，原值删除线 / 新值并排）与后端 `warnings`，点「💾 确认保存」才落盘；
  取消或预览失败都不发保存请求。
- **变更基线** - 基线是画布灌入时的有效配置（全局默认 ⊕ 技能 `config.json` ⊕ 空模型名的自动建议），
  灌进 widget 的默认值与自动建议模型不算变更。比例按数值判等（`1296:736` 与 `16:9` 视为同一比例）。
- **LoRA 剥离** - 导入时按 `config.loras` 注入的主链 LoRA 节点（数量 = LoRA 条数 − 模板槽位数）不计入模板结构：
  改 LoRA 值只报 `loras` 一行并把值写进 `config.json`，模板自带的 `{{LORA_i_NAME}}` 槽位原样保留。
- **只写工作流** - 回写只保存 API 工作流（节点、连线、widget 值）与同步后的 `config.json`；
  画布上的节点位置 / 颜色 / 分组 / 折叠等界面布局不写入，`skill.md` 正文保留。

### 变更记录

每次确认保存按技能记一条本机本地历史（`localStorage`，每技能最近 50 条，新→旧）：
技能详情工作流区「🕘 变更记录」查本技能，顶栏 🅝 菜单「📜 变更记录」查全部技能（按技能分组），均可清空；
记录仅本机可见，不影响技能文件。

## 语言版与按需读取

- 生成提示词时按语言只加载一版主文件（`skill.md` 英文 / `skill.cn.md` 中文，二者互斥），
  默认依据输入语言自动判断，也可在远程配置里固定为 `en` / `cn`。
- 子目录中的引用文件（如 `references/*.md`、`*.txt`）不预先并入提示词，
  而由模型通过工具按需读取；工作流参考图像素同样按需取回，以匹配渐进式披露设计并降低 token 消耗。
  本地与远程模式行为一致，仅在无引用且无工作流上下文时回退为单轮生成。
- 正文可包含 `<!-- @if TOKENS -->…<!-- @end -->` 条件段落（逗号分隔可多选）：
  token 为生成模式（T2VA / I2VA / FL2VA / L2VA / Reference）或参考媒体类型（PICTURES / VIDEOS / AUDIOS）。
  工作流上下文含 H3 节点时只注入命中 token 的段落并剥掉标记；无 H3 上下文、正文无标记或无交集时原样保留全文。
  `minimax_h3_base` 按模式裁剪约省 33%~40% token，`minimax_h3_full_ref` 按参考类型裁剪约省 20%。

## H3 格式自检

frontmatter 声明 `audit: h3` 的技能（`minimax_h3_base`、`minimax_h3_full_ref`、`minimax_h3_image_ref`）
在生成完成后先经过一次纯规则的结构审计（不花 token）：六段 / 三字段结构顺序、时间戳格式与时长上限、
参考标签与工作流连线一致性、对白说话人 ID、内部表示术语泄漏。

- 发现违规时发起一次「窄修复」LLM 调用，只修列出的违规项；
  修复结果须通过复审且参考标签集合、对白逐行不变才采纳，否则保留原输出（至多修复一轮）。
- 界面全程可见：正文照旧实时透传，生成结束后提示词框上方「📋 H3 流程」面板累计显示各阶段
  （自检中 / 通过 / 发现 N 处问题 / 自动修复中 / 已修复 / 修复未通过校验保留原输出），流结束后面板保留供回看。
- 走工具循环（技能带引用文件、或工作流 H3 节点连有参考图）的路径先显示
  「⏳ 生成中（按需读取技能引用文件 / 查看 N 张已连参考图）…」再逐字输出最终结果。
- 工作流上下文末尾会追加按模式判定的最终 grounding 约束，从源头降低结构错误率。
