# H3 Video (MiniMax H3 video generation)

> 🇨🇳 中文: [../h3-video-gen.md](../h3-video-gen.md)

MiniMax H3 video generation: single-segment BUNDLE and multi-segment director recipes. Recipe editing:
[recipes.md](recipes.md). Image generation: [image-gen.md](image-gen.md).

## Usage

### Multi-segment recipe (video_director)

- Pick a `recipe` (director recipe) in the node → segments are generated one by one → concatenated into a
  single `VIDEO` with audio.
- The node embeds a read-only timeline: click a segment block to open the editor positioned on that
  segment; ✎ in the top-right opens the editor.
- Hovering a segment block reveals a checkbox: run only the checked segments (a runtime state, never written
  into the recipe).
- During generation the timeline shows progress: current segment amber, finished green, pending with no bar.

### Single segment from a BUNDLE

- Wire in a `BUNDLE` (generated by `NeoPromptAgent`) → one segment runs, with `bundle_skill` picking the
  video skill.
- A non-empty `bundle_text` is appended after the skill prompt as a segment-level prompt.

## NeoH3VideoDirector (multi-segment director)

![Neo video generation nodes on the canvas](../assets/images/vide-gen.png)

- Inputs: `recipe` (required), `seed`, `MODEL`, `steps`, `BUNDLE` (optional), `bundle_skill`, `bundle_text`.
- Output: `VIDEO`, connect a SaveVideo.
- Each segment's `seed = base seed + segment index`: reproducible, and different per segment.
- Up to 99 segments; single-segment regeneration is described under "Regenerating one segment & merging".
- During sampling the node's preview panel shows frames live (auto-loop / pause / per frame / per step).

## Execution rules

### Chunking & modes

- **Segment by segment**: every segment uses its own skill template and configuration; prompt / duration /
  first frame come from that segment's fields.
- **Multi-frame single run**: consecutive compatible segments whose total duration is ≤ `shared.chunk_sec`
  (default 15s, `0` = off) are merged into one run.
  - A compatible segment must select a multi-frame skill (frontmatter `multi_frame: true`).
  - `t2v` / `i2v` / `fl2v` segments carry no own reference material; `r2v` segments may share a reference
    set, and every segment in the block must reference exactly the same set (same content, same order),
    otherwise the block breaks and falls back to segment-by-segment.
  - When merged, each segment's storyboard keyframe is pinned at the start and an `fl2v` last frame at the
    end; the multi-segment prompt is assembled mechanically as `[Shot N] At <timestamp> cut... <text>`, with
    no LLM call.
  - A segment with its own first frame takes the multi-frame path even when it is alone (a first frame can
    only be injected through a keyframe anchor).
  - In the editor's "🎞️ Storyboard timeline", after a multi-frame skill is selected the merged segments show
    a `⚡Ns` badge and a purple left-border preview.
- **Generation modes**: `shared.mode` (`f2v` / `r2v` / `mixed`) decides which frames and references each
  segment carries; in `mixed` the per-segment `seg.mode` applies. Older recipes without the field infer it
  from the segment's content (last frame → `fl2v`, first frame → `i2v`, only video/audio references → `r2v`,
  otherwise `t2v`).

  | Mode | Carries | Editor shows |
  |------|------|-----------|
  | `f2v` keyframe to video | decided by the first/last frame slots: no frame = text-to-video, first frame only = image-to-video, last frame only = L2VA, both = first-last frame | first-frame area + last-frame area |
  | `r2v` full-reference video | reference images ≤9 / reference videos ≤3 (the first is the source video) / reference audios ≤3 | reference media area |

  Validation: image-to-video and first-last-frame segments need a first frame (or the previous segment's last
  frame can be wired in), last-frame generation needs a last frame; before saving this is only a hint and does
  not block, at execution time it errors.

### Continuity & media

- **Cross-segment continuity**: with `continuity` on (the default), the previous segment's last
  `context_frames` frames (default 22) are injected as a video reference at the start of the next segment;
  that segment regenerates those frames first and drops the same number of leading frames when concatenating,
  so the seam has no duplicated frames.
  - The window frame count is snapped to the model's `17k+5` grid; the segment's target total frame count is
    its duration frames plus the window frames, snapped again.
  - Seam cross-fade: before dropping the window frames, the frames regenerated by this segment are blended
    with the previous segment's frames already in the film over 6 frames with weights 0→1, turning a hard cut
    into a gradient.
  - Storyboard first frame wins: when a segment has its own first-frame image, its anchor uses it; the
    previous segment's tail becomes a reference video placed "before the target" instead, with no duration
    change, no dropped frames and no fade — a hard cut between segments.
- **Identity references**: the recipe's "👤 character reference images" (≤4) are injected into every segment
  (including the first) and are the only identity anchor when the storyboard keyframes carry no face.
  - The "character identity references" checkbox is on by default; unchecking writes
    `shared.identity_refs=false` on save and the recipe stops injecting them.
  - Identity inheritance: the first segment that carries reference material contributes its reference images
    (≤4) as a supplementary source adopted by every later segment; images a segment already sent are not
    injected twice.
- **Reference limits**: one first frame and one last frame per segment, reference images ≤9 / reference videos
  ≤3 / reference audios ≤3; the order in the media list is the reference slot number.
- **Audio alignment**: the segment audios are concatenated in order, each seam discards the samples of the
  dropped frames, and the total audio length equals the duration of the concatenated frame count.

## Regenerating one segment & merging it back

- **Single-segment regeneration (♻)**: ♻ at the right of a segment title row in the director editor → pick a
  seed (🎲 new seed / reuse the node seed) and an anchor (both ends / first frame only / none).
  - The backend takes the real frames around the segment's frame range from the finished film: the first
    anchor = the previous segment's last frame (the first segment uses its own first frame), the last anchor =
    the next segment's first frame.
  - The segment is rewritten as `fl2v` (`i2v` when there is only a first anchor, original mode when no anchor
    is used) and runs alone with the new seed.
  - The resolution follows the finished film being redone; when the recipe's shared resolution differs from
    the film, it says so explicitly.
  - The product goes to `output/neo_director_regen/<recipe>_s<segment>_<timestamp>.mp4` and is recorded in the
    recipe's `results`; the original film is untouched.
- **Anchor source**: with several finished films in the recipe, the panel offers an "anchor source" dropdown
  (latest film by default); naming a file that is not among the recipe's results errors explicitly. When the
  frame count does not match the segment boundaries it errors and names the film; when the recipe has no film
  yet, the anchor degrades to "no anchor" automatically, which is the single-segment debugging path.
- **Single-segment debug node `NeoH3SegmentRun`**: pick recipe + segment number + anchor + seed; leaving
  `film` empty uses the latest film; with `record` off it only outputs `VIDEO` for your own SaveVideo.
- **How it runs**: generation runs as a node in ComfyUI's execution queue, so VRAM, progress and cancellation
  are the executor's job; the frontend polls the job state once a second and shows "queued… / generating… x%",
  with sampling preview on the plugin's own preview channel.
- **Merging back**: the replaced segment becomes the new clip and every other segment is taken from the
  original film, producing a new complete film.
  - Untouched segments take their frames and audio straight from the original film, seams are hard cuts, and
    audio is trimmed per segment frame count to keep A/V aligned. Mismatched segment resolutions and frame
    counts that do not match the boundaries error explicitly instead of forcing a splice.
  - The product goes to `output/neo_director_merge/<recipe>_merged_<timestamp>.mp4`, and the recorded
    `results` entry carries the real per-segment frame counts, so later regenerations default to taking
    anchors from it and several segments can be redone in a row. Neither the original film nor the segment
    clips are modified.
  - Merging calls no model and occupies no execution queue slot; progress is reported by frame count.

## Storyboard grid splitting

- **Node `NeoGridSplit`**: pick a storyboard grid image with separators or margins; rows and columns are
  detected and split automatically, and the cells are output as an `IMAGE` batch in row-major order together
  with the prompts embedded in the original. Rows × columns can be set by hand; when detection fails it falls
  back to a single cell or an even split. Grid images are produced externally, and an image card in the asset
  panel can be dragged straight onto the node.
- **Editor entry**: the "🧩 Grid storyboard" card on the "📖 Storyboard" page, see [recipes.md](recipes.md).
  Splitting replaces the existing segments: each cell becomes that segment's first frame and storyboard image
  (`i2v`), and the shared aspect ratio follows the panel ratio automatically.

## Timeline & interaction

- The node's read-only timeline reuses the editor's component; clicking a segment block opens the editor
  positioned on that segment (when the window is already open it only switches the current segment).
- ✎ in the top-right opens the editor (keeping the current segment). After a workflow restore, the timeline
  refetches the restored recipe automatically.
- Saving a director recipe from any entry broadcasts an update, and every Director node's `recipe` dropdown
  refreshes its candidates and reloads its timeline immediately.
- Inside a segment block the reference images are tiled side by side filling the block height (order = slot
  number); videos and audios appear as count badges.
- When there are many segments or the view is zoomed, the current segment scrolls into view automatically.

## Templates & configuration

### Skill directory & model resolution

Each video skill directory contains:

- `skill.md`: frontmatter with `gen_video: true`, body is the prompt template
- `workflow.json`: the H3 sampling chain template
- `config.json`: model / size / duration / steps defaults

Model resolution priority: skill `config.json` → the global "video generation model" setting → automatic pick
by name clues → error. The audio VAE is resolved separately and must stay separate from the video VAE.
`width` / `height` / `length` are defaults and can be overridden by node inputs.

### Single-shot generation on the Video page

The Video page (one line of text plus material, one finished clip, via `/neo_video_gen/simple`) shares the
same two-pane "skill + custom parameters" chip as the drawing pages. Skills are grouped by generation mode,
and the group headers are the director page's two words: **Keyframe → video** (t2v / i2v / fl2v) and
**Full-reference video** (r2v). The media slots follow the family: the keyframe family shows the first /
last frame slots, the full-reference family shows the reference image / video / audio slots. Slots hidden by
the family are excluded from the request, and they are intact again when you switch back.
The panel and the chip option menus open 6px above the chip whenever they fit there (below only when
the space above is too small) and stay clamped inside the window: with the dock pinned to the window
bottom the panel opens upward, so main model / steps / "Done" never end up below the fold.

- The panel's custom parameters are a **per-request override**: main model / Text Encoder / video VAE /
  audio VAE / LoRA / steps are sent in the body only when non-empty (`model` / `text_encoder` / `vae` /
  `audio_vae` / `loras` / `steps`); the backend merges them into the skill config and runs the same
  resolution chain. Empty means keep following the skill's `config.json` and the global "video generation
  model" setting.
- The panel prefills the steps field with the value the skill's `config.json` pins (the shipped effect skill
  pins 24). **Leaving that field untouched sends no `steps`**, so the skill's steps are what run; a positive
  value becomes this request's override, and `-1` / `0` mean "follow" (the same sentinel as the Director
  node's `steps`).
- Skills with `requires_ref: true` are blocked in the frontend when material is missing: a storyboard skill
  without a first / last frame, or a full-reference skill without a reference image, sends nothing and the
  status line names what is missing.
- Every tier in the resolution chip has a landscape and a portrait entry: `352p / 432p / 576p / 720p /
  768p / 1080p`, one entry per MiniMax H3 canvas step (short edge 768, area cap 768×1344); portrait is the
  same tier with width and height swapped, so `768p` portrait is `768×1344`. The chip carries the drawing
  page's ratio glyph, which stands tall on a portrait tier. The picked size goes out in the body as
  `width` / `height`, and Regenerate fills a portrait size stored in the side file back into the panel.

### Template variables

| Variable | Meaning |
|------|------|
| `{{MODEL}}` | Diffusion model |
| `{{TEXT_ENCODER}}` | Text encoder |
| `{{VAE}}` | Video VAE |
| `{{AUDIO_VAE}}` | Audio VAE (must be independent of the video VAE) |
| `{{WIDTH}}` / `{{HEIGHT}}` | Output size |
| `{{LENGTH}}` | Output frame count |
| `{{SEED}}` / `{{STEPS}}` | Seed / sampling steps |
| `{{PROMPT}}` / `{{NEGATIVE}}` | Positive / negative prompt |
| `{{REF_IMAGE}}` | First frame image |
| `{{REF_IMAGE_LAST}}` | Last frame image |
| `{{REF_IMAGE_1}}`…`{{REF_IMAGE_9}}` | Reference images |
| `{{REF_VIDEO_1}}`…`{{REF_VIDEO_3}}` | Reference videos |
| `{{REF_AUDIO_1}}`…`{{REF_AUDIO_3}}` | Reference audios |
| `{{LORA_1_NAME}}`…`{{LORA_5_STRENGTH}}` | LoRA slots |

- Reference placeholders that are not supplied are pruned together with their loader nodes, so a template can
  declare every maximum slot.
- A first-last-frame template with only one side degrades to I2VA / L2VA; with neither it reports "this skill
  needs reference images".
- A supplied reference conditions the model on its own: a filled `ref_images.ref_image_N` /
  `ref_videos.ref_video_N` slot of `MiniMaxH3ReferenceToVideo` enters the conditioning whether or not the
  prompt names it.
- `<Picture i>` / `<Video k>` / `<Audio j>` says what a given reference is for, and measures as a small
  difference. A supplied kind the prompt never names gets a binding line appended before execution (the
  audit's per-kind 1-based numbering); prompts that already name their references are left alone, and the
  first frame of the image / first-last skills needs no tag and gets none, because it binds through the
  first-frame anchor rather than a reference slot.

### Runtime injection

Runtime injection (when the template has no matching slot):

| Injection | Purpose | Injected node |
|------|------|---------|
| Context window | Cross-segment continuity + identity reference images | `NeoH3AddContext` |
| Multi-frame keyframes | Keyframes of each segment of a multi-frame skill | `NeoH3AddGuides` |
| Single-frame anchor | First / last frame anchor (hand-built graphs and legacy workflows) | `NeoH3AddKeyframe` |
| LoRA | Every LoRA in the configuration | `LoraLoaderModelOnly` |

- The injected nodes are chained between the H3 conditioning node and the sampler, and the sampler's `model` /
  `positive` / `negative` come from that injection chain.
- Injection does not change the output frame count or frame rate; it applies to this run only, does not touch
  core, and does not take over patches owned by other plugins.
- In a hand-built graph, chain `NeoH3AddContext` (or `NeoH3AddKeyframe` for a single-frame anchor) between
  `MiniMaxH3*ToVideo` and the sampler.

### Effect skill presets (H3 effects)

An effect skill carries a table of effects: `config.json`'s `effects` pins, per effect, the prompt template,
the example prompt, the effect body file, the duration cap and the first/last-frame rule. The skill's own
`steps` is the shot default the Video page prefills - the effect entries carry no step count.
The Effects dropdown on the Video page is that table, and the frontend sends nothing but an effect id.
Three shipped skills carry one: 关键帧家族's `effect_h3` (first frame plus one line, defaulting to 子弹时间)
and 全参考家族's `minimax-h3-r2v` / `minimax-h3-vdn-r2v` (entry-for-entry the same table, defaulting to
无特效). `workflow.json` is each skill's own H3 template (image-to-video or reference-to-video), and
`resolve_video_params` resolves the shot from the selected entry - the single-segment, simple-video and
director paths all run through that one resolution chain:

| Key               | Meaning                                                                        |
|-------------------|--------------------------------------------------------------------------------|
| `effect`          | The skill's default effect id; used when the request body carries no `effect`  |
| `effects[]`       | The effect table; each entry carries the contract in the rows below            |
| `id: "none"`      | The fixed id of the 无特效 entry: the prompt goes in as written, with no embedding segment and no frame cap |
| `prompt_template` | Prompt template; `{text}` takes the user's line, and a template without `{text}` replaces it entirely |
| `prompt_default`  | What fills `{text}` when the line is empty; also the Video page placeholder for that effect |
| `embedding`       | Effect body filename under `models/embeddings/`; missing for the selected effect, the run is refused and the file is named |
| `same_first_last` | The last frame defaults to the first frame (a closed shot, so the clip loops); an explicit last frame wins |
| `max_length`      | Frame cap; a longer duration on the page is clamped back to it                 |

The effect body is a community text embedding: the backend appends the official trigger segment
`embedding:<filename>` to the final prompt (ComfyUI 0.30+ supports `embedding:name` in H3 prompts; the trigger
is the filename without extension, matched verbatim). The files ship from
[Comfy-Org/MiniMax-H3/embeddings](https://huggingface.co/Comfy-Org/MiniMax-H3/tree/main/embeddings), made by
[silveroxides](https://huggingface.co/silveroxides) ([discussion #50](https://huggingface.co/Comfy-Org/MiniMax-H3/discussions/50));
they are not MiniMax official work. The shipped effect skill `effect_h3` (特效-特效镜头, first frame plus one
line, 11 effects):

| Effect id          | Label        | Effect body (`models/embeddings/`)                       | Frame cap          |
|--------------------|--------------|----------------------------------------------------------|--------------------|
| `bullet_time`      | 子弹时间     | `minimaxh3_bullet_time.safetensors`                      | 124 frames         |
| `frozen_moment`    | 定格瞬间     | No file (base-model approximation plus identical first and last frames, loops) | 124 frames         |
| `art_is_explosion` | 画面炸开     | `minimaxh3_art_is_explosion.safetensors`                 | none               |
| `blooming_flowers` | 繁花盛开     | `minimaxh3_blooming_flowers.safetensors`                 | none               |
| `dark_magic`       | 黑暗魔法     | `minimaxh3_dark_magic.safetensors`                       | none               |
| `fire_breath`      | 火焰吐息     | `minimaxh3_fire_breath.safetensors`                      | none               |
| `four_seasons`     | 四季流转     | `minimaxh3_four_seasons.safetensors`                     | none               |
| `kiss_camera`      | 亲吻镜头     | `minimaxh3_kiss_camera.safetensors`                      | none               |
| `spiral_ascent`    | 螺旋升腾     | `minimaxh3_spiral_ascent.safetensors`                    | 124 frames         |
| `storm_magic`      | 风暴魔法     | `minimaxh3_storm_magic.safetensors`                      | none               |
| `truman_show`      | 楚门式片场   | `minimaxh3_truman_show.safetensors`                      | none               |

- The embedding is a text condition - the `embedding:` segment is resolved in the CLIP text encoder, independent
  of the conditioning node type ([discussion #50](https://huggingface.co/Comfy-Org/MiniMax-H3/discussions/50)) -
  so the 全参考家族 presets `minimax-h3-r2v` / `minimax-h3-vdn-r2v` carry the same table's 10 embedding effects
  plus 无特效, and no 定格瞬间 (that one closes the shot by repeating the first frame, and
  reference-to-video has no last-frame slot). Their shipped default is 无特效: with it selected the prompt goes
  in as written, a plain reference shot sends no effect, and the skill stays available even when none of the
  embeddings are on disk; picking an effect runs that entry's contract (frame cap and the hard
  missing-file refusal included), sampled at the 20 / 8 steps the preset pins.
- The skill stays available in the skill dropdown as long as one effect body is installed; the effect whose
  body is missing is marked （不可用） in the Effects dropdown instead of disappearing from the list.
- The effect table carries no step count: 24 / 28 is MiniMax's reference for the un-accelerated official
  model, and the shots people actually run are a distilled checkpoint plus a speed-up LoRA, where those
  numbers only slow the shot down. Typing 8 into the panel's steps field really runs 8 steps; leaving that
  field untouched runs the skill's own 24.
- The 特效视频 preset card of the home page's 开始创作 section (off the default home - add it back through
  编辑首页 → 添加卡片) takes the skill-card route straight to the Video page with this skill selected, and the
  Effects dropdown lands on the shipped default effect.
- Submitting on the Video page first asks the readiness check against the `models.json` manifest for the
  selected effect, and the notice jumps straight to the Model Hub; a missing body of any other effect does not
  block this shot. A request that skips the frontend is refused in `resolve_video_params` with
  "effect 子弹时间 is missing its embedding file: <file>". This hard refusal is required: when ComfyUI cannot
  resolve an `embedding:` segment it only warns, ignores the segment and finishes the run, which yields a clip
  with no effect at all.
- The source and license of the embedding files live in the preset's `models.json` `license` field and in the
  body of `skill.md`; commercial use of locally generated output needs a MiniMax commercial license. The effect
  skill mounts no LoRA, and every other video skill keeps the existing behaviour of generating without a
  missing LoRA plus a warning.
- The `skills/presets/effect_bullet_time` and `skills/presets/effect_frozen_moment` folders an older build
  seeded into the data root are not removed on their own and stay in the skill dropdown (presets are read-only,
  the UI deletes no preset): delete those two folders under `<data root>/skills/presets/` to drop them.
- The effect skill pins more steps than the general presets, so the Video page's default skill (the
  available skill with the fewest steps) stays a general preset.
- H3 is guidance-distilled and its template pins `cfg` at 1.0: effects ship no negative prompt, and the look
  comes from the positive template plus the embedding segment.

## Per-skill settings & export from canvas

- The "🎬 Video generation settings" area of the skill detail dialog sets the video model / steps / Text
  Encoder / VAE (video) / VAE (audio) / LoRA per skill.
- Changes to a preset skill go to a local override file and leave the preset file untouched; "↺ Restore
  defaults" clears the override in one click.
- The header's "Copy as custom" icon button produces an editable custom skill that keeps `gen_video` and `category: video_gen`.
- "📋 From Canvas" in the skill dropdown exports the current canvas API prompt as a skill; when an H3 video
  workflow is detected it is saved as a video skill and templated by placeholders.

## VDN acceleration (optional plugin ComfyUI-VDN-H3)

- Five built-in VDN variant presets: text-to-video / image-to-video / first-last frame / reference-based /
  continuous multi-segment (`(VDN)` suffix).
- They are structurally identical to the non-VDN presets, with a single extra `ApplyVDNH3Advanced` between
  `UNETLoader → MiniMaxH3SigmaShift`, and `steps` set to 8 (matching the 8-step DMD-distilled checkpoint).
- Needs ComfyUI-VDN-H3 installed and the 8-step stage in `models/vdn/stage-dmd-step-250/`.
- Without that plugin, execution reports "VDN acceleration plugin ComfyUI-VDN-H3 required" clearly before
  sampling, telling you to install it and restart, or to use a non-VDN skill; the skill dropdown also marks
  them "(unavailable)", and the default skill of a new recipe skips unavailable ones.
- For a different stage, use "Copy as custom" and change `vdn_checkpoint` in the template.

## Runtime acceleration: external `MODEL` / `steps`

- `NeoImageGenEdit` and `NeoH3VideoDirector` accept an external `MODEL` input, so a model can be swapped
  temporarily without touching the skill template (per segment for video / for a single segment).
- When a `MODEL` is supplied, only the pure model chain along the `model` input edge is cut (UNETLoader / LoRA
  / VDN nodes); the shared text encoder / video VAE / audio VAE / sampler nodes are kept, and the injection
  point's output is replaced by the external model.
- `steps` (default `-1`): `-1` = the skill's configured value; `>0` = overrides the rendered `{{STEPS}}`.
- Typical use: wire the output of `ApplyVDNH3Advanced`, or of a quantized / distilled model, into `model`, and
  you get acceleration without a VDN preset.

## Live preview

- During sampling, 8 frames are sampled evenly along the latent timeline at every step, decoded to color,
  downscaled to a 1024 longest side, and pushed to the client that started the run.
- The payload carries the node id, and the frontend routes it to that node's animation panel.
- The same decoded frames are stored a second time at a 384 longest side for the right agent dock: that card is only
  that wide, and SSE carries nothing the card cannot show. The WS broadcast and the polling fallback never carry it.
  Which tier the agent SSE takes is decided by the request's `preview_side`: with the center stage on the painting page
  it asks for the 1024 tier; with the sampling preview switched off the request sends 0, `_preview_of` does not read the
  preview tables at all, and the SSE carries no `preview` payload.
- A segment run's payload is addressed by the node id the submitting request carries; a route submission with no node
  is addressed by the task id (same as a whole film), and the terminal state clears both caches.
- Without taeh3 weights, or when decoding fails, it falls back to the core default preview and never blocks
  the output.

## Notes

- The terminal `CreateVideo` packs video frames + audio into a native `VIDEO` (fps=24) and does not write to
  disk itself; add a SaveVideo to export a video with sound.
- Sampling steps resolve in this order: a positive value in this request (the Video page's panel / the node's
  `steps`) > the skill's `config.json` `steps` > default 20; the effect table carries no steps. cfg /
  sampler / scheduler are written in each skill's `workflow.json`.
- The shipped 24-step default and the effect tables of the two reference presets travel into the data root with
  the code: `seed_presets()` refreshes a shipped copy nobody touched and leaves a file the user changed alone.
  A preset whose steps the user edited keeps that value — change the steps in 技能管理 to get the shipped
  default. A preset's `skill.md` in the data root is the document copy seeded at the time and is never
  rewritten; delete that one file to get the new document on the next start.
- The model dropdown under "output settings → video generation model" puts the H3-related entries first, which
  makes local models easy to find.
- Video has no "depends on reference images" concept: every configured LoRA is loaded unconditionally.
