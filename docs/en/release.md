## Release

### What goes into the package

`.comfyignore` (gitignore syntax) decides what the Registry package contains: comfy-cli takes the files
git tracks minus the entries listed there. `tests/`, `tools/`, `.github/`, `.vscode/`, `test-results/`,
`pytest.ini`, `package.json` and the rest of the development files are excluded; the runtime `.py`
files, `web/` (including the `web/docs/` node help), `configs/`, `skills/`, `prompts/`,
`example_workflows/` and README/LICENSE/pyproject/requirements stay in. Untracked local files
(`node_modules/`, `tmp/`, the gallery caches, `configs/backyard_oss.json`) are already excluded by
`.gitignore` and need no entry here. The app repository's `README_ZH.md`, `Developer.md` and `docs/`
live outside `studio/` and are not part of the Registry package.

Registry installs read only the `dependencies` in `pyproject.toml`; `requirements.txt` serves
ComfyUI-Manager and the development environment, and the two have to stay aligned. Optional extras
(`laya` / `pillow-heif` / `oss2`) live in `[project.optional-dependencies]`.

Registry and frontend search hits come from the `description` / `keywords` in `pyproject.toml` and the
nodes' own `SEARCH_ALIASES` (convention: "Node metadata" in [architecture.md](architecture.md),
validated by `tests/test_node_metadata.py`).

The 3D Pose page ships its build as `studio/pose_dist/` (tracked in git, generated by
`tools\build_pose_package.ps1`, 3.9 MB: the code plus the CC0 figure `ybot.glb`, plus `LICENSE` /
`THIRD-PARTY.md` / `models/ATTRIBUTION.md` / a `MANIFEST.json` with a sha256 per file). The full build
in the data root lives under `data/pose/dist/`, and `data/` is not packaged - the user's scenes,
reference images and imported figure GLBs all live there too. What ships is decided by the licence rows
in the pose repository's `models/ATTRIBUTION.md` (Mixamo and the SMPL-derived bodies stay out), and
`tools\test_pose_package.ps1` verifies the manifest file by file, size cap included - see
[studio-pose.md](studio-pose.md). The manifest compares bytes, so the repository's `.gitattributes` pins
`pose_dist/` to no line-ending conversion (`-text`, with GLB / wasm / ktx2 marked binary): on a machine with
`core.autocrlf=true` a checkout would hand back CRLF text, every byte count and sha256 would stop matching,
and the self-check would report a perfectly good package as corrupt.

### Git Action route

- Registry metadata lives in `[tool.comfy]` inside `studio/pyproject.toml` (PublisherId
  `neoneo-ai`, DisplayName `Neo Studio`).
- `.github/workflows/publish.yaml`: on a `v*` tag push, a Release publish, or a manual trigger, it runs
  `comfy node publish --token` inside `studio/` (needs the `COMFY_REGISTRY_PUBLISH_TOKEN`
  secret). Publishing has to run at that level: `pyproject.toml` and `.comfyignore` are both in
  `studio/`, and the root `pyproject.toml` is the Studio desktop's own manifest.

```bash
# 1. Bump the version (to 1.0.1 for example): edit version = "1.0.1" in studio/pyproject.toml
git add studio/pyproject.toml
git commit -m "Bump version to 1.0.1"

# 2. Tag it (pointing at that new commit)
git tag v1.0.1

# 3. Push code + tag, publishing is triggered
git push origin main v1.0.1
```

### comfy cli route

```bash
cd studio
comfy node publish    # enter the API TOKEN when asked
```

## Desktop build & source install

```powershell
# Studio desktop packaging: onefile single file / onedir folder build / both;
# the payload = studio's git-tracked files
tools\build_studio_exe.ps1 [-Mode onefile|onedir|both] [-DryRun]
tools\build_studio_exe.ps1 -Mode both -Sign -CertThumbprint <thumbprint>   # signtool signing + verify
tools\build_studio_exe.ps1 -Notarize -AppleTeamId <TeamID>          # macOS notarytool (macOS only)
tools\build_studio_exe.ps1 -Publish                                  # comfy node publish

# Source install of the kernel plugin: code and built-in presets only, writes the
# configs/data_root.json data-root pointer, never deletes anything in the target directory
# The script is UTF-8 without BOM, run it with pwsh (PowerShell 7); Windows PowerShell 5.1
# reads the Chinese comments as mojibake
pwsh -NoProfile -ExecutionPolicy Bypass -File tools/install_plugin.ps1 -ComfyUI <ComfyUI root> -DataRoot <data root> [-SkipDeps] [-DryRun]
```

**Rebuild the exe after changing `app/studio_app.py`.** Running the desktop from source syncs
`studio/` into `custom_nodes` on every launch (same-named files only, nothing in the target is
deleted); the exe only swaps the plugin directory when its bundled copy's version is newer, and a git
checkout is never touched.

The window and taskbar icon is the clapperboard `web/neo-studio.ico`, generated by
`tools/make_studio_icon.py`; the launcher is built with the same icon.

### Release workflow

`.github/workflows/release-app.yml` runs the same `build_studio_exe.ps1` on `windows-latest` when a
`v*` tag is pushed (or on a manual dispatch) and attaches the result to that tag's GitHub Release:

- `Neo-Studio-<version>-windows-x64.exe` — the onefile single file, about 52 MB
- `Neo-Studio-<version>-windows-x64-portable.zip` — the onedir build zipped whole (`Neo-Studio.exe`
  plus `_internal/`; unzip and use the folder as-is, no unpacking at launch, so the window shows up
  faster)

The default is `both`, so a tag attaches both forms; for a manual dispatch that builds only one, type
`onefile` or `onedir` into `mode`.

The assets are unsigned, so expect a SmartScreen prompt on first run; signing and notarization stay
local (`-Sign` / `-Notarize`), since CI has no machine certificate and cannot run the macOS path.
Publishing to the Registry is `publish.yaml`'s job — the two workflows are independent.

CI builds on Python 3.12, matching the locally verified build.

### CLR hosting fallback

The desktop window is pywebview's WinForms backend, which needs pythonnet to host .NET. On some machines the
.NET Framework (netfx) hosting fails — `Python.Runtime.Loader.Initialize` cannot be resolved inside the
AppDomain and no window opens. The desktop imports clr itself before `webview.start()` and, on failure,
overrides `pythonnet`'s runtime with coreclr and loads it again: pywebview's own coreclr fallback is inert
under pythonnet 3.x (the netfx runtime object already occupies `pythonnet._RUNTIME`, so re-importing after
setting the environment variable reuses the broken netfx). coreclr needs the desktop runtime
(`System.Windows.Forms` lives in `Microsoft.WindowsDesktop.App`), so the bundle ships
`tools/coreclr.runtimeconfig.json` → `_internal/runtime/`. A switch logs `clr switched to coreclr` into
`data/studio_desktop.log`.

## Offline tools

The scripts under `tools/` build and deploy the asset presets; they are never loaded by the ComfyUI
runtime:

```bash
# 0. Package builder: turn an asset package into a preset directory (image + same-named .txt sidecar +
#    角色索引.txt); the package table is `--list`
python tools/build_gallery_presets.py --list
python tools/build_gallery_presets.py --pkg <cloud dir> [--out <presets root>] [--compress 0.25] [--sample 5]
#    --compress 0.25 writes each image at a quarter of its source bytes (JPEG quality ladder, then
#    downscale): the 3D three-view packs are 8-10 MB PNGs, so one 200-image pack is 2 GB uncompressed.

# 1. Preprocess: scan the preset directories, generate thumbnails and index.json (ffmpeg is needed for
#    video thumbnails)
python tools/gallery_preprocess.py --presets <presets_dir> --output <output_dir> [--size 320]

# Incremental mode: only add/update the named subdirectories (files deleted from the source are cleaned
# up in sync), pulling the latest index.json from OSS (configs/oss_presets.json -> index_url) as the
# merge base; every other directory is left alone. --no-fetch-index merges with the local index.json
# instead, --fetch-index <url> states the source explicitly.
# --presets may be omitted: the current working directory is used by default (just put the new and
# updated directories under it)
cd <dir_with_new_dirs> && python tools/gallery_preprocess.py --output <output_dir> --dirs dir1 dir2

# Staged release: --draft writes only the directory index <dir>/index.json and leaves the master index
# untouched, so the asset page does not show it yet; --publish mounts already written directory indexes
# into the master index without rescanning media.
python tools/gallery_preprocess.py --output <output_dir> --dirs dir1 dir2 --draft
python tools/gallery_preprocess.py --output <output_dir> --publish dir1 dir2

# Split a legacy full index into the layered layout: --split-legacy turns an index.json whose entries
# carry items into <dir>/index.json files plus a v2 master index
python tools/gallery_preprocess.py --output <output_dir> --split-legacy

# Tags only: --tag-dirs tags or clears tags on directories already in the master index, with no media
# rescan and no move of their home-section position (tags are directory attributes, a directory can
# carry several; directories the master index does not list keep the tags they already have)
python tools/gallery_preprocess.py --output <output_dir> --tag-dirs dir1 dir2 --tag character-sheet
python tools/gallery_preprocess.py --output <output_dir> --tag-dirs dir1 --clear-tags

# 2. Deploy: upload the preprocessed output to Aliyun OSS (needs pip install oss2,
#    credentials from OSS_ACCESS_KEY_ID / OSS_ACCESS_KEY_SECRET / OSS_ENDPOINT)
python tools/gallery_deploy_oss.py --source <output_dir> --bucket <bucket> --prefix <prefix>
```

The preprocessed output is a layered index: `index.json` is the v2 master index (one `count` / `index` /
`rev` / `covers` entry per directory), the full item list of a directory is in `<dir>/index.json`, and the
media copies and thumbnails are in `<dir>/` and `thumbnails/<dir>/`. The deploy script uploads the whole
output directory recursively, so directory indexes travel with their media; `.json` gets no long-cache
header, so an index change takes effect at once. The deployed OSS source is configured through
`configs/oss_presets.json` and pulled at runtime by `gallery_oss.py` into `gallery/oss_cache/`.

The Backyard page (`/neo-studio-backyard`) follows the same incremental semantics: its source directory is
resolved against the data root, and a source directory that holds the media files directly
(`data/gallery/presets_src/<one preset dir>`) is processed as one incremental directory. The merge base is the
cloud `index.json` from `configs/oss_presets.json -> index_url` first, and the output directory's local
`index.json` only when that fetch fails — so a machine that never ran the preprocessing locally cannot wipe
the other cloud directories. Ticking "完成后上传 OSS" chains the upload right after the preprocessing and
skips files whose ETag already matches; the key prefix gets its trailing `/` added, so a prefix written as
`/neo/presets` still lands on the cloud `neo/presets/index.json`. When an upload writes new files, the
gallery's cloud index cache is force-refreshed (the same path as `/neo_gallery/sync_oss`), so the new
directory shows up on the asset page at once; without that refresh it stays invisible until the
`sync_interval_hours` cache (24 h by default) expires. The "⟳ Refresh index" button in the asset page's
"Manage Directories" dialog hits the same endpoint, so the cloud index cache can be force-refreshed by hand at any time.

The upload page opens with a pending-upload list (`GET /neo_backyard/upload_plan`): per directory the item
count, the file count and the size to upload, classified against the cloud master index as "to upload" (the
cloud has no such entry), "updated, to upload" (the `rev` differs from the cloud — a legacy full index has no
`rev`, so any rescanned directory counts), "unpublished" (`--draft` wrote only the directory index, the master
index has no entry), or "synced", with a summary line for the pending directories, files and total bytes.
With no cached cloud index every directory is listed as pending and the page says there is nothing to compare
against. Upload and preprocessing output streams line by line over SSE, the progress bar follows each
`[i/total]` line, and the list reloads itself when the run finishes.
