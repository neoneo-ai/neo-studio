# Canvas

Images and prompts, laid out on one canvas. The canvas page puts image nodes, prompt nodes, generation nodes, video nodes and cars (the 车厢 of a laid-out 导演页 recipe) on the same zoomable, pannable board; the connections between nodes decide which prompts and reference images an 出图 or 出片 run carries, and where the finished images and clips land. The page lives in `studio/web/studio/pages/canvas/` (`page.js` is the page, with `geometry.js` / `nodes.js` / `interactions.js` / `store.js` / `history.js` / `gen.js` under it), and one canvas's nodes and connections land in `canvas/<canvas id>.json` under the data root.

## Where this page is

- The `canvas` view of the Studio shell: the same path in the desktop window and in the plugin page (`createCanvasPage` in `studio/web/studio/studio-app.js`). "Place on canvas" in the material library and the gallery sends the picked assets here and lays them out as image nodes on a non-overlapping grid, each one sized to the image's own ratio.
- The desktop window opens this page with no ComfyUI runtime: all five `/neo_canvas/*` routes are in the canvas group of `app/studio_caps.py`, and reading and writing a canvas is a pure file layer. The generation and video runs need the execution queue, so pressing 出图 / 出片 offline starts ComfyUI for the user and says "Generation needs the ComfyUI queue - it is starting, press again once it is up" instead of locking the button.

## The toolbar

The toolbar is one row that never wraps: every control is an icon button, its name in the tooltip and its `aria-label`,
and the keyboard chord in the tooltip of the ones that have a shortcut. When the window is narrower than the row, the
bar scrolls sideways inside itself (no scrollbar shown) instead of dropping to a second row. A thin divider separates
the three groups.

- **Canvas group**: one button on the bar carrying the current canvas name with a chevron - this group shows no icon button. It opens a list of canvases pinned under the button: a row's name switches to that canvas, the 重命名 and 删除画布 icon buttons are tucked at the right end of every row - they fade in when the pointer enters that row and when the keyboard tabs into it (a touch build keeps them lit) - and each one acts on that row's canvas only; the last row is 新建画布. With no saved canvas the list has no rename or delete to press. Deleting a canvas asks for confirmation and takes `canvas/<canvas id>.json` with it.
- **Node group**: one 加节点 drop-down (it opens as the five rows 加图片 / 加提示词 / 加生成节点 / 加视频节点 / 添加配方, pinned under the button), then 撤销 (Ctrl+Z) and 重做 (Ctrl+Shift+Z or Ctrl+Y). The four clipboard acts stay on the keyboard: 复制选中 is Ctrl+D, 剪切选中 Ctrl+X, 复制 Ctrl+C and 粘贴 Ctrl+V, and each one takes nodes or a connection. Every row in that menu shows its icon with its name next to it (the name stays in the tooltip and the `aria-label` too). Picking a row closes the menu, and so do the 加节点 button itself, a press outside the bar and Esc. With nothing to undo or redo those two sit greyed, and a greyed one stays greyed under the pointer.
- **View group**: zoom out / the current percentage / zoom in, then after a divider 适应内容 and 背景 (the dots / fine lines / blank cycle), and at the far right the save status slot (未保存 / {seconds} 秒后保存 / 已保存 / 保存失败 / 离线).

The first button is 停用 / 启用; an empty image node gains 选图 (open the library and take one), image nodes have 设为主图, and every node has 复制节点 and 删除节点. Connections live on the node's four sides - left and top take a line in, right and bottom send one out: start at an out point and drag onto another node and that is a connection; releasing on empty ground says "A connection has to land on a node". The four points stay faded out of the way and light up only on the node you hover, on the selected nodes and on the node a drag is aiming at (a touch build keeps them lit). Two nodes stacked vertically wire along the vertical axis - out of the bottom edge into the top edge - so the prompt block chain expand lays above a car, and the references below it, plug straight into the car's top and bottom edges instead of looping around the right side. The four corner handles change this node's width and height, and the arrow keys nudge the selected nodes by 8px (40px with Shift), every step undoable.

## The card on a generation node

| Control           | What it does                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---               | ---                                                                                                                                                                                                                                                                                                                                                                                                           |
| Skill chip        | One chip with an icon and the skill name, sized to its content; opening it switches to another entry of the image-generation skill list from the skills page, and a freshly laid node defaults to the last one used. The 主模型 line on the card reads that skill's config: the model name when it can be read, 「主模型：跟随技能配置」 when it cannot.                                                                     |
| The parameter row | Ratio, long edge and count share one row, one chip each, each chip's meaning in its tooltip. Ratio and long edge default to following the skill config and the global generation settings - the chip then reads 「默认比例」 / 「长边尺寸」 - and an override shows the value in force; the ratio chip's icon is that ratio's shape. The count chip opens a pick from 1 to 8 (the backend eats at most 8 images per run). |
| 出图                | The primary button owning the last row: a filled primary block across it. While the run is going it settles to a soft fill, with its position and width unchanged.                                                                                                                                                                                                                                            |
| 取消任务              | Only appears while this run is queued or running; pressing it hands the dequeue to the backend and the node drops back out of the running state.                                                                                                                                                                                                                                                              |
| The status line   | "Queued" and "Generating {done}/{total}" follow that run's backend progress; when it fails the line carries the reason and the card turns red.                                                                                                                                                                                                                                                                |

- Every control writes into the node's `metadata` on the spot: undoable, travelling with a copied node and saving with the canvas. The chips, the buttons, the seed input and the 附加操作栏 buttons swallow the press (the browser has to deliver their click), and pressing one selects that node the way ComfyUI does - important on these cards, since a generation card and a train car are covered in controls, so a press that selected nothing left you guessing which card it landed on. Press-dragging anywhere else on a card drags that card: the segment summary, the 配方 prompt line, the reference count, the status and model lines are all drag handles, and the card's text is never picked up by the browser (`.ns-canvas-node` is `user-select: none`, and only the editing box and the seed input read back as selectable).
- The chip menus float on the page layer (`.ns-canvas-gen-menus`), not inside the node: the world layer carries a scale and nodes clip their own content, so putting a menu into either of those layers loses on both sides.
- The generation request carries the upstream prompts and reference images in connection order. With no usable line it says "Run a text or image line into this node first"; when that skill takes no text prompt it names the skill and asks for a reference image.
- Finished images fill the downstream empty image nodes in connection order; the leftovers create image nodes on the right, connected to this generation node, and one undo takes back every image this run laid down.
- Switching canvases or removing the source node detaches the run: the results do not write the old canvas, the page only says "The images are saved in the Output folder".
- A skill missing its API key says so and opens Skill Management to fill it; a failed submission reports "Generation failed", a finished one reports "Generated {n} images".

## The 出片 node and the 车厢

The 出片 node is that generation card with its kind switched to video (`metadata.kind = "video"`): the four chips become the skill, the duration and the size, and the last row is the 生成视频 outlined pill beside 取消任务 - 出图 keeps the card's primary button.

| Control           | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Skill chip        | The list is the 出视频 page's video-skill list (the `gen_video` entries of `/rs_prompts/skills`); a skill missing its API key says so and opens Skill Management to fill it.                                                                                                                                                                                                                                                                                    |
| Duration chip     | 2–32 seconds, one second per slot.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Size chip         | The first slot 跟随尺寸 follows the 出视频 page's shared global default (the `video_defaults` width / height); the rest are that skill's own ratios in 9 slots at a 1280 long edge. A size picked on the canvas writes back into that same shared default, and switching skills drops a size picked for the old one.                                                                                                                                            |
| 生成视频          | An outlined pill of the control row's size: it carries the upstream prompts in connection order and the first connected image as the reference, and a skill whose `requires_ref` is set is stopped on the canvas - with no reference image it does not enter the queue.                                                                                                                                                                                         |
| Recipe chip       | Which recipe a column runs is decided when the train is laid out and is stored on every car (`/rs_recipes/list` - the `type = \"video_director\"` rows whose `source` is not `preset`); the tail only writes that name out, it is not switched here (see "Laying a train with 添加配方"). |
| Segment / anchor  | That segment's skill and duration both read the recipe's own copy, edited on the 导演页; the three anchor slots (两端锚点 / 只钉首帧 / 不用锚点), the steps, the continuity and the context frames are in the tail's 参数 window. Its prompt and reference material default to that copy too; a connected text or image node is this run's canvas override.                                                                                                          |
| Reference row     | The car's top row carries this segment's reference count on its right: the material connected above the car counts first, ahead of that segment's own recipe assets, all in the one line. The assets themselves are the image nodes above the car - the card never repeats them as thumbnails.                                                                                                                        |
| Tail skill chip   | The chip on the tail: empty is every segment taking the skill that segment's recipe row stores, picking one pins it for the whole column; a recipe with no skill and an empty chip writes 「这份配方没有技能：在车尾选一个视频技能」 on the chip.                                                                                                                                          |
| Tail size chip    | The chip on the tail: empty follows this recipe's shared resolution (the `shared` width / height), picking one pins the whole column's clips to it, written into the tail's `metadata.width` / `height` and carried by every segment run.                                                                                                                                                    |
| 参数 window       | The tail's 参数 opens a window holding the five uncommon parameters - steps, anchor, continuity, context frames, seed - one chip menu or one number per row (the dropdowns are the page's own chip menus, not native selects, and they open inside the window so the scrim never covers them); the window states 每一段的时长跟着配方走, and a click outside, the × and Esc all close it.                                                                      |
| Seed              | The number box in that window: empty is a new seed per segment, a number is that seed plus the segment index, and the edit lands in the tail's `metadata.seed` on the spot.                                                                                                                                                                                                                 |
| Top-row sentence  | The shared sentence appears on the tail's top row once - 「链上 {n} 段 · 启用 {m} 段 · {配方名}」; a car's top row writes 「段 {n} · 配方名 · 时长 · 生效技能 · 参考素材计数」. Both rows are the same layout, and no card lays a second overview line.                                                                                                                                       |
| Prompt source     | One row naming which prompt this run uses: 「画布」 lifted to the primary color when a text node feeds this car, and 「车厢」 once the car's box was edited; following the recipe's own prompt for that segment carries no label. An empty box carries the recipe's prompt for that segment; editing writes it into `metadata.content`, saved the same way a prompt node saves it, and it travels with undo, with a copied node and with the canvas. While a connected prompt is what runs, the box is locked - that run sends the connected text, so editing the box changes nothing - and cutting the line lands back on the car's own copy.                |
| 取消任务          | The same button as on the image card: pressing it hands the dequeue to the backend. |
| The status line   | The same line as on the image card: 「生成中 {done}/{total}」 reads the snapshot's own progress; when it fails the line carries the reason and the card turns red. |
| 停用 / 启用       | The first button of the bar that floats above a selected node: it writes `metadata.disabled` for every node type; a disabled node dims, pins the 「已停用」 badge, and 出图, 出片 and a column run all skip it (see "The tail and the column run"). |
| What a car holds  | 添加配方 lays one car per segment (`metadata.recipe` + `metadata.segment`): the card writes the segment number, that segment's skill and duration, where its prompt and reference material come from plus a preview of them, and it carries no button at all (停用, 复制 and 删除 are in the bar above the node). Anchor, continuity, context frames, steps, seed and 生成视频 are not on it - which segments the column runs, how it runs and the whole run live on that column's single tail generation node (see "Laying a train with 添加配方" and "The tail and the column run"). |

- 出片 runs the 出视频 page's own backend chains: a simple clip goes to `/neo_video_gen/simple` and one recipe segment to `/neo_video_gen/run_segment` (a chain column is that same route, one call per segment), with the status and the cancel on the same `/{task_id}` and `/{task_id}/cancel` layer - the routes and the response shape are in [出视频与导演闭环](h3-video-gen.md).
- The seed lives only on the chain tail card: the number box on it, where `-1` means a new seed per segment (the default), 0 and any negative value fold back to `-1`, and a positive number pins it and each segment takes that seed plus its segment index. The 出片 card keeps no seed box and the simple chain always sends `-1`; reproduce one simple clip by filling the seed box on the 出视频 page.
- The finished clip writes back into the first empty video node downstream (`metadata.filename` + `subfolder`, played through `/neo_gallery/video`); a disabled node is not a landing slot, so the run keeps looking, and with none free it creates one at the lower right, connected to this run, and one undo takes back the node it created.
- While the run is going the node carries the running state (animated border and label) and a second send is refused until that run ends.
- Switching canvases, leaving the page or deleting the node stops that clip's polling: a detached clip writes its own node only, never the canvas you left.

## Laying a train with 添加配方

添加配方 is a row of the 加节点 drop-down: it opens a recipe picker reading `/rs_recipes/list`, each card carrying the recipe name and its overview line (段数 · 模式 · 技能 · 宽高 · 总时长). Picking a card lays that recipe on the canvas as one train - the picker closes by itself, the whole batch of nodes and edges lands in a single undo entry, and afterwards they are ordinary nodes. When the list cannot be read (offline, the recipe was never saved) the picker says so; a recipe over the column cap (24 segments) says so and lays nothing.

| What gets laid    | What it is                                                                                                                        |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| One car           | One 车厢 node per segment (`metadata.recipe` + `metadata.segment`), 3 cars per row (9 segments land as 3×3 and 6 as two rows of 3, lining up with the 九宫格 / 六宫格 storyboard grids of the 出视频 page), head to tail connected into chain edges (`previous car → next car`) |
| Car reference     | That segment's **image** assets land directly above their own car (at most 5 per car), connected into it, each node carrying `metadata.asset` + `metadata.recipe`; reference videos and audios are not laid as nodes - the backend takes them from the recipe's own copy when that segment runs |
| The tail          | One generation node per column (`metadata.chain = "train"`, `metadata.kind = "video"`), placed in the slot right after the last car; the one shared video skill and the anchor / continuity / context frames / steps / seed all live on that card |
| Switching recipe  | Which recipe the column runs is fixed when it is laid and stored on every car, the tail only writes it out; to run another recipe, press 添加配方 again and lay a new train |
| One edit          | The laid nodes and edges are one undo entry - undo takes the whole batch back; afterwards they are ordinary nodes: the text edits, the chips swap, a copy carries them and the canvas saves them |
| 停用 (in the bar) | The bar's first button writes `metadata.disabled`: the column run skips that car, the car dims with the 「已停用」 badge, and pressing the column run with every car disabled says one line and sends nothing |

Laying says 「已铺好 {n} 段：参考素材按连线接进每一厢，出片与整列共用的技能在车尾」, the selection lands on the freshly laid cars, and the view pulls itself back onto the column (`fitView`).

A car runs the same chain, handing its references in the three groups `references.images` / `references.videos` / `references.audios`, and one material connected by two lines still counts once:

| The connected node            | What the payload carries                                                |
| ---                         | ---                                                                     |
| An image node (a canvas file) | `{"kind": "input", "value": "sub/file.png[output]"}`                  |
| An asset node (a recipe file) | `{"kind": "recipe", "value": "asset.png", "recipe": "RecipeName"}`    |

The backend lands both classes in the input folder before the load node sees them (`_reference_name` in `studio/image_gen.py`): each is copied to `input/NeoAgent/<name>_<timestamp><ext>`. A missing recipe, a missing asset file, a name carrying a path separator or `..`, or a suffix outside that media type drops that one reference with a backend log line, and the run itself goes ahead.

## The tail and the column run

The chain is layout and order only: a car is a compact card — the segment number, that segment's skill and duration, where its prompt and reference material come from plus a preview of them, and no button on the card at all (停用, 复制 and 删除 all live in the bar above the node) — the edges and the disable flag are canvas state, and running stays on the 导演页's per-segment closed loop with no second execution path.

- The chain order walks from the tail upstream to the head and flips back (`segment 0 → segment 1 → … → segment N`); a cut chain stops at the segment it reached, and a loop is recognised.
- The tail's 生成视频 queues the enabled segments one after another, each one a `/neo_video_gen/run_segment` - ComfyUI's own queue runs them in submit order, each clip lands in its own downstream video slot (connected to that segment's car), and the tail lands none.
- The shared parameters exist on the tail only: the skill and the resolution chips sit on the tail card (both empty follows the recipe, picking one pins the whole column), while anchor, continuity, context frames, steps and seed are kept in the tail's 参数 window; the seed offsets by segment index (the tail's value is the starting point, `-1` means a random seed per segment).
- 停用 on a car is the first button of the bar above the node and writes `metadata.disabled`: the column run skips that segment and the car dims with the 「已停用」 badge. A car is display only — 生成视频, the recipe, anchor, continuity, context frames, steps and seed all stay on the tail.
- The shared sentence appears on the tail's top row once: that row writes 「链上 {n} 段 · 启用 {m} 段 · {配方名}」, and the recipe name is the one every car of this column stores; a car writes none of it. The tail's top row and a car's top row share one layout (the same `.ns-canvas-car-head` row), so the two read identically on the canvas. Running another recipe means laying a new train with 添加配方.
- The tail's 取消任务 cancels every segment that column is running; a running column writes 「串联出片 {done}/{total}」 on the status line, and a failure keeps the backend's reason there.
- A broken chain speaks instead of running on defaults: a tail with no cars upstream says 「这台生成节点上游没有车厢：用「添加配方」铺一列」, and a column with every car disabled says 「链上没有启用的段」 - neither sends a request.
- The tail's parameters go through `metadata` and save with the canvas (`metadata.chain = "train"`, a disabled car's `metadata.disabled = true`); a car's `metadata.train` and a tail's `metadata.expand_mode` written by an older build read back untouched and the current build never writes them, and an older canvas without those keys is enabled and not a chain.

## Undo and saving

Undo and redo are two stacks in `pages/canvas/history.js`: the stacks record only nodes and connections, never the viewport or the background; the depth is capped at 60, and switching or creating a canvas clears them. One drag and one stretch of typing count as a single change, so one undo takes back the whole stretch.

Changes accumulate in this page's memory and land on disk 900ms after the last one, viewport and background included; leaving the page saves first. The indicator at the right end of the toolbar is whether this one landed. `canvas/index.json` is a list cache - delete it and the list is rebuilt from the canvas files; deletion only exists as the single-item route the UI offers, and nothing clears the whole `canvas/` folder.

## `/neo_canvas/*`

| Method | Route                 | What it does                                                   |
| ---    | ---                   | ---                                                            |
| GET    | `/neo_canvas/list`    | The canvas list (the index plus canvas files the index missed) |
| GET    | `/neo_canvas/project` | One canvas's nodes and connections (`?id=`)                    |
| POST   | `/neo_canvas/project` | Saves one canvas: the write layer refuses an unfinished JSON   |
| POST   | `/neo_canvas/rename`  | Changes the title                                              |
| POST   | `/neo_canvas/delete`  | Deletes one canvas                                             |

The backend is `studio/canvas.py`: writes go through a temporary file swap under one lock for concurrency, a node's `type` is stored exactly as the page wrote it (`image` / `text` / `gen` / `video` / `recipe` and any face this build does not know yet keep their name, and only a missing one becomes `text`, so an older page falls back to the text face itself), and the offline desktop service answers the same group of routes, so the plugin and the offline window write the same file.
