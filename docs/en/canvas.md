# Canvas

Images and prompts, laid out on one canvas. The canvas page puts image nodes, prompt nodes, generation nodes, video nodes and recipe-closed-loop nodes on the same zoomable, pannable board; the connections between nodes decide which prompts and reference images an 出图 or 出片 run carries, and where the finished images and clips land. The page lives in `studio/web/studio/pages/canvas/` (`page.js` is the page, with `geometry.js` / `nodes.js` / `interactions.js` / `store.js` / `history.js` / `gen.js` under it), and one canvas's nodes and connections land in `canvas/<canvas id>.json` under the data root.

## Where this page is

- The `canvas` view of the Studio shell: the same path in the desktop window and in the plugin page (`createCanvasPage` in `studio/web/studio/studio-app.js`). "Place on canvas" in the material library and the gallery sends the picked assets here and lays them out as image nodes on a non-overlapping grid.
- The desktop window opens this page with no ComfyUI runtime: all five `/neo_canvas/*` routes are in the canvas group of `app/studio_caps.py`, and reading and writing a canvas is a pure file layer. The generation and video runs need the execution queue, so pressing 出图 / 出片 offline starts ComfyUI for the user and says "Generation needs the ComfyUI queue - it is starting, press again once it is up" instead of locking the button.

## The toolbar

The toolbar is one row that never wraps: every control is an icon button, its name in the tooltip and its `aria-label`,
and the keyboard chord in the tooltip of the ones that have a shortcut. When the window is narrower than the row, the
bar scrolls sideways inside itself (no scrollbar shown) instead of dropping to a second row. A thin divider separates
the three groups.

- **Canvas group**: the canvas drop-down (switch the current canvas), with the 重命名 and 删除画布 icon buttons tucked at its right end - they fade in when the pointer enters that row and when the keyboard tabs into it (a touch build keeps them lit), while 新建画布 stays lit next to the row. Deleting a canvas asks for confirmation and takes `canvas/<canvas id>.json` with it.
- **Node group**: one 加节点 drop-down (it opens as the five rows 加图片 / 加提示词 / 加生成节点 / 加视频节点 / 加配方节点, pinned under the button), then 撤销 (Ctrl+Z) and 重做 (Ctrl+Shift+Z or Ctrl+Y). The four clipboard acts stay on the keyboard: 复制选中 is Ctrl+D, 剪切选中 Ctrl+X, 复制 Ctrl+C and 粘贴 Ctrl+V, and each one takes nodes or a connection. Every row in that menu shows its icon with its name next to it (the name stays in the tooltip and the `aria-label` too). Picking a row closes the menu, and so do the 加节点 button itself, a press outside the bar and Esc. With nothing to undo or redo those two sit greyed, and a greyed one stays greyed under the pointer.
- **View group**: zoom out / the current percentage / zoom in, then after a divider 适应内容 and 背景 (the dots / fine lines / blank cycle), and at the far right the save status slot (未保存 / {seconds} 秒后保存 / 已保存 / 保存失败 / 离线).

Connections live on the node's four sides - left and top take a line in, right and bottom send one out: start at an out point and drag onto another node and that is a connection; releasing on empty ground says "A connection has to land on a node". The four points stay faded out of the way and light up only on the node you hover, on the selected nodes and on the node a drag is aiming at (a touch build keeps them lit). Two nodes stacked vertically wire along the vertical axis - out of the bottom edge into the top edge - so the prompt block chain expand lays above a car, and the references below it, plug straight into the car's top and bottom edges instead of looping around the right side. The four corner handles change this node's width and height, and the arrow keys nudge the selected nodes by 8px (40px with Shift), every step undoable.

The 主模型 line on the card reads that skill's config: the model name when it can be read, 「主模型：跟随技能配置」 when it cannot.                                                                     |

Ratio and long edge default to following the skill config and the global generation settings - the chip then reads 「默认比例」 / 「长边尺寸」 - and an override shows the value in force; the ratio chip's icon is that ratio's shape. | 出图                | The primary button owning the last row: a filled primary block across it. While the run is going it settles to a soft fill, with its position and width unchanged.                                                                                                                                                                                                                                            |
| 取消任务              | Only appears while this run is queued or running; pressing it hands the dequeue to the backend and the node drops back out of the running state.                                                                                                                                                                                                                                                              |
| The status line   | "Queued" and "Generating {done}/{total}" follow that run's backend progress; when it fails the line carries the reason and the card turns red.                                                                                                                                                                                                                                                                |

- Every control writes into the node's `metadata` on the spot: undoable, travelling with a copied node and saving with the canvas. The chips, the buttons, the 段 buttons, the seed input and the 附加操作栏 buttons swallow the press (the browser has to deliver their click), and pressing one selects that node the way ComfyUI does - important on these cards, since a generation card and a train car are covered in controls, so a press that selected nothing left you guessing which card it landed on. Press-dragging anywhere else on a card drags that card: the segment summary, the 配方 prompt line, the reference thumbnails, the status and model lines are all drag handles, and the card's text is never picked up by the browser (`.ns-canvas-node` is `user-select: none`, and only the editing box and the seed input read back as selectable).
- The chip menus float on the page layer (`.ns-canvas-gen-menus`), not inside the node: the world layer carries a scale and nodes clip their own content, so putting a menu into either of those layers loses on both sides.
- The generation request carries the upstream prompts and reference images in connection order. With no usable line it says "Run a text or image line into this node first"; when that skill takes no text prompt it names the skill and asks for a reference image.
- Finished images fill the downstream empty image nodes in connection order; the leftovers create image nodes on the right, connected to this generation node, and one undo takes back every image this run laid down.
- Switching canvases or removing the source node detaches the run: the results do not write the old canvas, the page only says "The images are saved in the Output folder".
- A skill missing its API key says so and opens Skill Management to fill it; a failed submission reports "Generation failed", a finished one reports "Generated {n} images".

The 出片 node is that generation card with its kind switched to video (`metadata.kind = "video"`): the four chips become the skill, the duration and the size, and the last row is the 生成视频 outlined pill beside 取消任务 - 出图 keeps the card's primary button.

- The finished clip writes back into the first empty video node downstream (`metadata.filename` + `subfolder`, played through `/neo_gallery/video`); a disabled node is not a landing slot, so the run keeps looking, and with none free it creates one at the lower right, connected to this run, and one undo takes back the node it created.
- While the run is going the node carries the running state (animated border and label) and a second send is refused until that run ends.
- Switching canvases, leaving the page or deleting the node stops that clip's polling: a detached clip writes its own node only, never the canvas you left.

## Expanding a recipe

The 配方闭环 node spreads its recipe onto the canvas: **展开配方** at the bottom of the card spreads that card, and that card is the only place this act lives. Expansion reads the same segment list from `/rs_recipes/list`, and how it lays them out is that card's 展开方式 slot (`metadata.expand_mode`, missing = flat).

- **Flat expand** (`"grid"`, the default): one row per segment in four columns — that segment's prompt as a text node, its reference material as image nodes (at most 4, in a 2×2 block), a segment node (the recipe, anchor, steps, continuity, context frames and seed carry over from the source card, with the segment index pinned to this segment) and an empty video slot to its right (where the clip lands). The connections come with it: the text and the material run into the segment node, and the segment node runs into the video slot. Each segment renders on its own.
- **Chain expand** (`"train"`): one car per segment along the main line, 4 cars per row, and the tail is a generation node at the end of the line (`metadata.chain = "train"`). Each car spreads three nodes: the car on its own row, that segment's prompt as a text node directly above it in the same column and the same width (360×220 - the whole prompt reads in one glance, and a scrollbar shows up only when the text overflows), and that segment's reference material as image nodes below it in the same column (at most 4, in a 2×2 block of 176×124 that fills the car's width). No video slot beside a car: where a clip lands is decided by the run itself - it fills a free downstream video node and opens a new one when there is none. A spread is at most 6 × segments + 1 tail node. The cars are wired end to end `segment 0 → segment 1 → … → segment N → tail`: the anchor, continuity, context frames, steps and seed shared by the whole column live only on that tail node, and a car carries just `recipe` and `segment`.

Expanding queues nothing; the selection lands on the freshly laid segment nodes, the view pulls itself back onto them, and it says 「已展开 {n} 段：每段一台段节点，提示词与参考素材连过去」 flat and 「已串开 {n} 段：段节点首尾相接，生成参数在车尾那台生成节点」 chained.

| The rules               | What they say                                                                                                                                                                                                                     |
|                         |                                                                                                                                                                                                                                   |
| Segment cap             | 24 segments; past that it says 「段数太多（{n} 段），展开上限 {max} 段」 and lays nothing.                                                                                                                                        |
| The material column     | At most 4 per segment, taken in the order `first_frame`, `storyboard`, then `refs`'s `images` / `videos` / `audios`.                                                                                                              |
| What an asset node holds| `metadata.asset` (the file name inside the recipe's `assets/`) + `metadata.recipe`, with no `filename`; the picture comes from `/rs_recipes/thumbnail?...&dir=assets` and falls back to the raw `/rs_recipes/asset` file.         |
| One change              | The laid nodes and connections go onto one undo entry, so one undo takes the whole spread back; after that they are ordinary nodes - the text is editable, the chips switch, a copied node carries them and the canvas saves them.|
| What it says            | A card with no recipe says 「先选一份配方」; an unreadable recipe list says 「配方列表读不到：先在导演页保存这份配方」.                                                                                                           |
| Expand mode             | That chip swaps 平铺展开 / 串联展开 into `metadata.expand_mode`, and the card's 展开配方 lays that slot.                                                                                                                          |
| The chain edge          | The edge carries layout and order, not execution: the tail's 生成视频 sends one `/neo_video_gen/run_segment` per segment in chain order, each clip lands in its own downstream video slot, and the tail itself lands none.        |
| 停用 (in the bar)       | The bar's first button writes `metadata.disabled`: the column run skips that car, the car dims with the 「已停用」 badge, and a column with every car disabled says 「链上没有启用的段」 when its 生成视频 is pressed.            |
| A broken chain          | A cut chain stops the tail's run at the segment it reached; a tail with no cars upstream says 「这台生成节点上游没有段节点：用串联展开铺一列」 - it runs on no silent defaults.                                                   |

An expanded segment node runs the same chain, handing its references in the three groups `references.images` / `references.videos` / `references.audios`, and one material connected by two lines still counts once:

| The connected node            | What the payload carries                                                |
| ---                         | ---                                                                     |
| An image node (a canvas file) | `{"kind": "input", "value": "sub/file.png[output]"}`                  |
| An asset node (a recipe file) | `{"kind": "recipe", "value": "asset.png", "recipe": "RecipeName"}`    |

The backend lands both classes in the input folder before the load node sees them (`_reference_name` in `studio/image_gen.py`): each is copied to `input/NeoAgent/<name>_<timestamp><ext>`. A missing recipe, a missing asset file, a name carrying a path separator or `..`, or a suffix outside that media type drops that one reference with a backend log line, and the run itself goes ahead.

## Chain expand: the tail node and the column run

The chain is layout and order only: a car is a compact card — the segment number, that segment's skill and duration, where its prompt and reference material come from plus a preview of them, and no button on the card at all (停用, 复制 and 删除 all live in the bar above the node) — the edges and the disable flag are canvas state, and running stays on the 导演页's per-segment closed loop with no second execution path.

- The chain order walks from the tail upstream to the head and flips back (`segment 0 → segment 1 → … → segment N`); a cut chain stops at the segment it reached, and a loop is recognised.
- The tail's 生成视频 queues the enabled segments one after another, each one a `/neo_video_gen/run_segment` - ComfyUI's own queue runs them in submit order, each clip lands in its own downstream video slot, and the tail lands none.
- The shared parameters (anchor / continuity / context frames / steps / seed) exist only on the tail; the seed offsets by segment index (the tail's value is the starting point, `-1` means a random seed per segment), the same rule the flat expand uses per segment.
- 停用 on a car is the first button of the bar above the node and writes `metadata.disabled`: the column run skips that segment and the car dims with the 「已停用」 badge. A car is display only — 生成视频, the recipe, anchor, continuity, context frames, steps and seed all stay on the tail.
- The tail's 取消任务 cancels every segment that column is running; the tail's overview row writes 「链上 {n} 段 · 启用 {m} 段」, a running column writes 「串联出片 {done}/{total}」, and a failure keeps the backend's reason on the status line.
- A broken chain speaks instead of running on defaults: a tail with no cars upstream says 「这台生成节点上游没有段节点：用串联展开铺一列」, and a column with every car disabled says 「链上没有启用的段」 - neither sends a request.
- The tail's recipe and parameters go through `metadata` and save with the canvas (`metadata.chain = "train"`, a car's `metadata.train = 1`, `metadata.expand_mode = "train"`, a disabled car's `metadata.disabled = true`); an older canvas without these keys is flat, enabled, not a chain.

## Undo and saving

Undo and redo are two stacks in `pages/canvas/history.js`: the stacks record only nodes and connections, never the viewport or the background; the depth is capped at 60, and switching or creating a canvas clears them. One drag and one stretch of typing count as a single change, so one undo takes back the whole stretch.

Changes accumulate in this page's memory and land on disk 900ms after the last one, viewport and background included; leaving the page saves first. The indicator at the right end of the toolbar is whether this one landed. `canvas/index.json` is a list cache - delete it and the list is rebuilt from the canvas files; deletion only exists as the single-item route the UI offers, and nothing clears the whole `canvas/` folder.

## `/neo_canvas/*`

| Method | Route                 | What it does                                                   |
| ---    | ---                   | ---                                                            |
| GET    | `/neo_canvas/list`    | The canvas list (the index plus canvas files the index missed) |
| GET    | `/neo_canvas/project` | One canvas's nodes and connections (`?id=`)                    |
| POST   | `/neo_canvas/project` | Saves one canvas: the write layer refuses an unfinished JSON   |
| POST   | `/neo_canvas/rename`  | Changes the title                                              |
| POST   | `/neo_canvas/delete`  | Deletes one canvas                                             |

The backend is `studio/canvas.py`: writes go through a temporary file swap under one lock for concurrency, a node's `type` is stored exactly as the page wrote it (`image` / `text` / `gen` / `video` / `recipe` and any face this build does not know yet keep their name, and only a missing one becomes `text`, so an older page falls back to the text face itself), and the offline desktop service answers the same group of routes, so the plugin and the offline window write the same file.
